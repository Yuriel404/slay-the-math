# 《数字尖塔》游戏设计文档 v0.3

> 当前可玩规格。v0.2 的规划背景见 [设计与技术方案 v0.2](game-plan-v0.2.md)，v0.1 草案归档于 [v0.1](archive/game-design-v0.1.md)。v0.3 在同一条规则内核上扩展了内容、决策反馈与视觉表现，并把交付形态扩展为**桌面应用 + 浏览器**双宿主。

## 定位

单人、回合制、卡牌构筑、肉鸽。以电脑为优先平台，极简几何风，暗色奇幻牌桌。

数学是分配资源与构造攻防的机制，玩家无需自行心算，界面始终展示最终效果与算式。

玩家通过产数牌获得数字，使用加工牌改变它们，再填入攻防卡槽位。成长来自奖励选牌、铭刻、净化与后续路线选择。

完整规划为三幕；当前实现为七层短流程。概率师、分叉地图、商店、事件与后续两幕仍保留为扩展内容。

## 基础规则

| 项目 | 当前规则 |
| --- | --- |
| 初始角色 / 生命 | 代数师 / 60 |
| 每回合能量 / 抽牌 | 3 / 5 张 |
| 手牌上限 | 10；额外抽到的牌进入弃牌堆 |
| 数字池容量 | 6；超出后必须先点击弃置多余筹码 |
| 数域 | 0～99 的非负整数 |
| 筹码身份 | 每枚独立，同值筹码能分别用，同一枚不能重复用 |
| 确认 / 取消 | 填槽、替换、取消免费；确认才消耗能量与筹码 |
| 护甲 | 挡伤后扣减，玩家下一回合开始清零 |
| 单次数值效果 | 向下取整，负伤害/护甲为 0，单次上限 99 |
| 加工越界 | 不可确认，明确显示原因，不截断数字 |
| 胜利 | 敌人全部死亡立即胜利，跳过其后敌方行动 |

回合顺序：清除玩家护甲 → 恢复能量 → 起始遗物与保留数字 → 抽牌 → 公布意图 → 玩家行动 → 回合末能力 → 弃牌、清空数字 → 敌人行动。

本回合已公布的敌人意图不变，受伤后切换阶段只影响下一回合。

起始遗物「常数表」每回合获得一个 2。起始牌组：常数×4、变量 x×1、打击×1、防御×2、累加×1、双联×1。

### 休息点三选一

| 选项 | 效果 | 代价 |
| --- | --- | --- |
| 休息 | 回复最大生命的 30% | — |
| 铭刻 | 把 1、2 或 3 永久刻入一张攻防卡的一个槽位 | — |
| 净化 | 从牌组中永久移除一张卡牌 | 25 金币，且牌组不得少于 5 张 |

金币由此获得第一个真实用途：普通战斗 +15、首领 +35，休息点的净化是当前唯一的消费出口。

## 当前 21 种卡牌

| 卡牌 | 类别 | 能量 | 稀有度 | 规则 |
| --- | --- | ---: | --- | --- |
| 常数 | 产数 | 0 | 普通 | 获得一枚 3 |
| 变量 x | 产数 | 1 | 普通 | 选择 1～4，获得两枚相同数值的独立筹码 |
| 打击 | 攻击 | 1 | 普通 | 造成 n 点伤害 |
| 防御 | 防御 | 1 | 普通 | 获得 n 点护甲 |
| 累加 | 攻击 | 1 | 普通 | 将两数相加，选择攻击或防御 |
| 差值 | 攻击 | 1 | 普通 | 造成 a − b 点伤害，结果不小于 0 |
| 双联 | 攻击 | 2 | 稀有 | 造成两数乘积伤害 |
| 质数之刃 | 攻击 | 1 | 稀有 | 质数槽，造成 2n 伤害 |
| 奇刃 | 攻击 | 1 | 稀有 | 奇数槽，造成 2n 伤害 |
| 偶数壁垒 | 防御 | 1 | 稀有 | 偶数槽，获得 1.5n 护甲，向下取整 |
| 平方壁 | 防御 | 2 | 传说 | 平方数槽，获得 1.5n 护甲，向下取整 |
| 平方 | 攻击 | 2 | 传说 | 造成 n² 伤害，消耗 |
| 微调 | 加工 | 0 | 普通 | 一枚筹码 +1 或 −1，结果仍须在 0～99 |
| 因式分解 | 加工 | 1 | 稀有 | 将合数拆为两个均大于 1 的整数因数 |
| 翻倍 | 加工 | 1 | 普通 | 将一枚筹码 ×2 放回池中 |
| 拆分 | 加工 | 1 | 普通 | 选择 a，将 n 拆成 a 和 n−a |
| 复制 | 加工 | 1 | 传说 | 消耗一枚筹码，获得两枚该数值的独立筹码 |
| 平衡 | 调度 | 1 | 稀有 | 两槽之和必须为 10，抽 2 张 |
| 洞察 | 调度 | 0 | 普通 | 抽 2 张牌，消耗 |
| 寄存器 | 调度 | 0 | 稀有 | 暂存一枚筹码，下回合返还，每回合限一次 |
| 余项 | 能力 | 1 | 传说 | 持续能力，回合末每枚未用筹码对所有敌人造成 1 点伤害 |

普通牌结算后进入弃牌堆；消耗牌进入消耗区；能力牌进入能力区。结算中的卡牌不参与当次抽牌洗牌。牌库耗尽时洗入弃牌堆，牌组身份始终守恒。

稀有度只驱动外观（外发光与角标），不改变规则，也不参与抽牌权重。

铭刻只允许攻防卡，值为符合槽位条件的 1、2、3。每张卡最多铭刻一个槽；此槽不再占用数字池筹码。铭刻槽仍参与敌人机制判断。

## 七层流程与敌人

`加法史莱姆 → 小史莱姆 ×2 → 休息 → 倍增虫 → 奇偶守卫 → 休息 → 埃氏筛`

四场普通战斗后各获得一次三选一卡牌奖励，可跳过。普通战斗金币 +15，首领 +35。休息点提供休息、铭刻、净化三选一。

| 敌人 | HP | 机制 |
| --- | ---: | --- |
| 加法史莱姆 | 24 | 攻击 4、6、8…… |
| 小史莱姆 | 10 | 攻击 2、3、4……，成对登场 |
| 倍增虫 | 18 | 攻击 2、4、8、16，之后保持 16 |
| 奇偶守卫 | 28 | 攻击 6；攻击卡槽内运算结果与回合奇偶不同时，伤害 ×0.5 |
| 埃氏筛 | 72 | 每回合轮换筛选因子 2、3、5；任一有效槽值为当前因子的倍数时，攻击额外 ×0.5 |

第 2 层是**双敌遭遇**：两只小史莱姆各自独立结算血量与意图，攻击卡必须指定目标，只有全部死亡才胜利。这使目标选择与「余项」的群体伤害第一次成为真实决策。

埃氏筛剩余生命按三等分进入阶段，攻击为 4 / 6 / 8。防御和加工不受筛选影响。零也是任意非零整数的倍数。界面显示当前与未来两回合的筛选因子与预计攻击。

结算顺序固定为：槽值与条件校验 → 槽内运算 → 卡牌倍率 → 敌人倍率 → 向下取整 → 上限。质数之刃的奇偶判断使用槽内的 n，再施加自身 ×2 与敌人倍率。差值的 `max(0, a−b)` 在**卡牌倍率之前**完成，因此预览与实际始终一致。

## 界面与决策反馈

### 视觉体系

界面从单一荧光绿升级为**多色牌桌**：靛紫底色 + 金色主色，每个卡牌类别拥有自己的色系，颜色只用于表意，不随机使用。

| 语义 | 色系 | 出现位置 |
| --- | --- | --- |
| 攻击 | 赤红 / 余烬 | 攻击卡边框与高光、意图气泡、受创提示 |
| 防御 | 青蓝 | 防御卡、护甲徽章、能量盾 |
| 产数 | 琥珀 | 产数卡、数字池筹码 |
| 加工 | 紫罗兰 | 加工卡、铭刻状态、图鉴 |
| 调度 | 薄荷绿 | 调度卡、自动填槽、保存状态 |
| 能力 | 品红 | 能力卡与能力区标记 |
| 生命 | 玫红 | 生命条、敌人血条 |
| 金币 / 传说 | 金色 | 主按钮、稀有度、塔楼 |

卡面由「费用宝珠 + 种类飘带 + 纹理插画面板 + 描述 + 槽位与稀有度页脚」构成；数字筹码是有厚度和倒角的实体筹码，质数筹码转为紫罗兰并带星芒。敌人拥有圆形站台、悬浮意图气泡与分段血条。

### 操作与信息

- 上方：生命、能量、遗物、金币与层数。
- 中央：角色、敌人、血量、当前意图，以及**未来两回合的攻击预测**。
- 右侧出牌面板：槽位、参数、完整算式、预计数值，以及**可选组合**列表。
- 下方：数字池和手牌；右下角是能量与结束回合。

新增的决策辅助：

1. **受创预估**：标题栏显示若现在结束回合将承受的净伤害。
2. **击杀提示**：预览伤害足以击杀当前目标时，确认按钮变为红色并标注「击杀」。
3. **可选组合**：按收益排序的前三种合法填法，点击即填入，兼顾教学与提速。
4. **可填筹码高亮**：当前槽位条件（质数 / 奇数 / 偶数 / 平方数）能接受的筹码会呼吸式描边。
5. **自动填槽带收益**：按钮直接显示自动填充可达到的数值。
6. **结束回合提醒**：仍有能量与可出的牌时，按钮下方提示。

支持点击与拖放填槽、Enter 确认、Esc 取消、牌堆与战斗记录查看。数字池超容量时暂停出牌和结束回合。

### 布局与适配

桌面 1280×720 起，战斗页在 720 高度内不产生纵向滚动；1920×1080 与 1440×900 放大卡面与角色。窄屏（≤760px）改为单列，出牌面板内嵌滚动，算式与确认按钮固定在面板底部。

## 存档与局外记录

- 每次有效命令后自动保存；**保存成功才展示新抽牌与奖励**。
- 失败时保留待存结果，可重试或导出。
- 存档包含完整状态、随机数状态、规则与内容版本；保存最近一个有效备份，支持经过校验的 JSON 导入导出。
- 同版本、同种子和命令序列必须可复现；预览不推进随机数。
- 本机记录卡牌/敌人发现、登顶成就和攀登历史，不改变角色基础属性。

两种宿主共用同一份状态与校验：

| 宿主 | 存储 | 导入导出 |
| --- | --- | --- |
| 浏览器 | IndexedDB（Dexie） | 浏览器下载 / 文件选择 |
| 桌面（Tauri） | 应用数据目录下的 JSON 文件，临时文件 + 原子替换 | 原生「另存为 / 打开」对话框 |

内容版本升级到 `0.3.0`，旧对局存档按既定策略拒绝导入并保留原文件。

## 技术与扩展

TypeScript + React + Vite 构成界面；规则核心不依赖 UI。桌面外壳为 Tauri 2，Rust 只负责持久化与文件对话框，不持有任何规则。

内容通过 Catalog 配置，卡牌效果和敌人行为通过注册表扩展。会话串行处理命令，经 SavePort 持久化后，再通过 EventPort 驱动表现。存储使用 Dexie / IndexedDB，校验使用 Zod，状态订阅使用 Zustand，轻量动画使用 Motion。

随机数使用 pure-rand 的 xoroshiro128plus，地图、战斗、奖励、事件持有独立随机流。验证采用 Vitest、fast-check、Playwright 和生产内核模拟器。

详细边界和增加内容的步骤见 [架构与扩展指南](architecture.md)，桌面构建见 [桌面版构建与运行](desktop.md)，交付与测试记录见 [初版验收](implementation.md)。

## 后续阶段

- M2：概率师、一幕 15 层分叉地图、商店、事件、更多卡牌与遗物。
- 概率师的重掷每次出牌执行一次，之后正常弃牌；骰盅提供每回合一次额外免费重掷。加工后的骰子筹码失去重掷资格；d4 最多追加一次。
- 第一幕继续使用非负整数；精英改用余数攻防奖励，不实现 v0.1 的分数生命骑士。
- 赌场选择应使用同净期望、不同波动，避免把不等价投注解释为公平选项。
- M3：函数山谷、矩阵空间、数论师与几何师、难度进阶及完整图鉴。
- 后续向量机制提供公共卡入口，各角色均可完成主线。
- 当前所有数值均为实验参数，扩大内容前先通过固定种子模拟与人工试玩校准。
