### 浏览器验证

Playwright 在 Chrome 与 Edge 上各 8 项全部通过（16/16，20.8s）。运行期间若同时进行 Rust 全量编译，开发服务器可能因资源争用中断；请在单独运行时执行。

- 菜单开始、点击填槽、取消与 Enter 双次确认不重复结算。
- 拖放与点击得到相同预览，`3 × 4 = 12 伤害` 一致。
- 超容量时禁止结束回合，刷新读档后继续弃数。
- 当前存档损坏时恢复有效备份，坏 JSON 导入不覆盖进度。
- 1280×720、1920×1080、390×844 下无横向溢出；桌面无纵向溢出，出牌面板 / 数字池 / 手牌完整落在视口内。
- 铭刻永久保存、下一战自动填入固定槽、刷新恢复；减少动画不改变状态。
- 失败后回到菜单并重新开始。
- 从菜单用生产内核走完整个七层流程，覆盖奖励、休息与首领战，并记录登顶成就。

### 首轮模拟

每种策略运行 50 局，固定种子前缀 `SPIRE-BALANCE`，使用当前内容与生产规则内核：

| 策略 | 通关 | 通关率 | 平均总战斗回合 | 平均累计损血 | 每局未用筹码 | 每局未用能量 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 攻击优先 | 36 / 50 | 72% | 23.24 | 72.86 | 25.92 | 10.10 |
| 防御优先 | 32 / 50 | 64% | 36.42 | 66.98 | 47.38 | 26.02 |
| 混合策略 | 40 / 50 | 80% | 24.40 | 69.12 | 27.50 | 12.14 |

与 v0.2 的六层流程相比（88% / 76% / 90%），新增一层双敌遭遇与四场普通战斗把混合策略通关率压到 80%，并把「攻击优先 > 防御优先」的顺序修正为更符合直觉的方向。累计损血可超过最大生命，因为休息会回血。策略仍是简单启发式，本表只验证闭环并提供比较基线，不能替代人工试玩。

普通战斗约 4～5 回合，首领约 7 回合，略高于「普通 2～4 / 首领 6～10」的原始目标，后续调参待人工试玩。

## 当前限制

- 地图固定七层；金币只有休息点净化一个消费出口，仍无商店。
- 菜单只开放代数师；其他角色可通过 `CharacterDefinition` 与 `createRun` 接入。
- 数学图鉴提供卡牌/敌人机制与发现记录，暂没有逐概念的课程或算式回放收藏。
- 对局导出包含完整游戏和随机状态；图鉴与历史为本机记录，不随对局 JSON 迁移。
- 内容版本升到 `0.3.0`，v0.2 的存档会被明确拒绝并保留原文件。
- 当前没有随机效果卡牌；四条随机流已用于确定性洗牌、奖励及后续预留。
- 默认不播放音效。启用后使用合成反馈，无背景音乐。
- 存档迁移注册接口已提供；尚无真实旧版已发布存档需要转换。

## 本地复跑

```powershell
pnpm install
pnpm build                          # tsc --noEmit + vite build
pnpm test                           # 58 项规则与存档测试
pnpm test:e2e --project=chrome --project=edge --workers=2   # 16 项浏览器验收
pnpm simulate 50                    # 固定种子平衡模拟
pnpm preview --port 4273            # 另开窗口
pnpm shots                          # 重新生成 docs/screenshots
pnpm desktop:check                  # Rust 侧类型检查
pnpm desktop                        # 打开桌面窗口
```
